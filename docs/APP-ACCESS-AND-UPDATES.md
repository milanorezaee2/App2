# راه‌اندازی کنترل دسترسی و به‌روزرسانی برنامه

این قابلیت‌ها به migration جدید نیاز دارند؛ هیچ SQL یا Edge Function از طرف ما روی Supabase اجرا نشده است.

## ۱. اجرای SQL در Supabase

۱. در Dashboard پروژهٔ Supabase، **SQL Editor** را باز کنید.
۲. اگر هنوز schema پایه و راه‌اندازی قبلی انجام نشده، ابتدا `SETUP-COPY-PASTE-ONCE.sql` و سپس `CHAT-PUSH-SETUP-COPY-PASTE.sql` را اجرا کنید.
۳. محتوای `supabase/APP-ACCESS-UPDATE-SETUP-COPY-PASTE.sql` را کپی و اجرا کنید؛ این بخش باید بعد از migration کاربران مدیر، به‌ویژه `202610140002_registered_users_admin.sql`، اجرا شود.

مدیر سپس در تب **کاربران ثبت‌شده** می‌تواند حساب ثبت‌شده را مسدود یا دوباره مجاز کند. مسدودسازی با اتصال بعدی برنامه به اینترنت (یا حداکثر پس از تازه‌سازی دوره‌ای) اعمال می‌شود. اگر گوشی آفلاین باشد، سرور نمی‌تواند همان لحظه آن را قفل کند. این کنترل برای حساب‌هایی است که در فهرست کاربران ثبت‌شده دیده می‌شوند؛ مکالمه و محتوای درس‌ها تغییر نمی‌کند.

## ۲. روش سادهٔ ساخت APK با کلید موقت

در اجرای دستی workflow، گزینهٔ `temporary_signing` به‌طور پیش‌فرض روشن است و برای ساخت APK به Secret امضا نیاز ندارد. این کلید فقط برای همان اجرای workflow ساخته می‌شود. گزینهٔ `publish_release` را برای انتشار در GitHub Releases روشن کنید.

**محدودیت مهم:** APKهای ساخته‌شده در اجراهای مختلف کلیدهای متفاوت دارند. برای هر انتشار تازه، کاربر باید APK قبلی را حذف و APK جدید را دوباره نصب کند؛ دادهٔ محلیِ همگام‌نشده ممکن است پاک شود. اگر به‌روزرسانی معمولی بدون حذف برنامه می‌خواهید، از روش امضای پایدار زیر استفاده کنید.

## ۳. روش امضای پایدار (اختیاری)

برای نصب نسخهٔ تازه روی نسخهٔ قبلی، همهٔ APKها باید با همان کلید همیشگی امضا شوند. گزینهٔ `temporary_signing` را در workflow خاموش کنید و این چهار GitHub Actions Secret را تنظیم کنید:

- `ANDROID_RELEASE_KEYSTORE_BASE64`
- `ANDROID_RELEASE_STORE_PASSWORD`
- `ANDROID_RELEASE_KEY_ALIAS`
- `ANDROID_RELEASE_KEY_PASSWORD`

در GitHub: **Settings → Secrets and variables → Actions → New repository secret**. کلید خصوصی را در فایل‌های Git یا release قرار ندهید. اگر کلید گم شود، انتشار update روی نصب‌های قبلی ممکن نیست.

> APKهای انتشار قبلی با کلید موقتی CI امضا شده‌اند. اولین انتقال از آن‌ها به کلید پایدار، یک‌بار حذف نسخهٔ قبلی و نصب نسخهٔ جدید را لازم دارد و ممکن است دادهٔ محلیِ همگام‌نشده پاک شود. پیش از آن از پشتیبان داخلی برنامه استفاده کنید.

## ۴. ساخت و انتشار نسخه

۱. در GitHub، **Actions → Build MiloMultilang Android APK → Run workflow** را باز کنید.
۲. شاخهٔ `arena/9f71189a-app2` را انتخاب کنید. برای ساخت نسخهٔ معمولی، `russian_only` را خاموش بگذارید. برای انتشار در Releases، `publish_release` را روشن کنید.
۳. برای کلید موقت، `temporary_signing` را روشن بگذارید؛ برای کلید پایدار، آن را خاموش کنید و چهار Secret بالا را آماده داشته باشید.
۴. پس از موفقیت build و emulator smoke-test، صفحهٔ Releases لینک مستقیم فایل‌های APK را می‌دهد.

## ۵. انتشار از اپ مدیریت

پس از اجرای SQL و نصب APK مدیریتی جدید:

۱. تب **به‌روزرسانی** را باز کنید.
۲. برای هر برنامه نسخهٔ منتشرشده، کمترین نسخهٔ مجاز، لینک مستقیم فایل درست و یادداشت را وارد کنید. نام APK برای هر package در همان کارت مشخص است.
۳. ذخیرهٔ اعلان اختیاری، پیام دانلود قابل‌بستن نشان می‌دهد. روشن‌کردن **به‌روزرسانی اجباری** برای برنامه‌های پایین‌تر از حداقل نسخه، همهٔ صفحه‌های اپ را قفل می‌کند تا نسخهٔ تازه نصب شود.
۴. ابتدا روی نسخهٔ اختیاری و یک دستگاه آزمایشی امتحان کنید؛ سپس حداقل نسخه و حالت اجباری را فعال کنید. برای بازگرداندن دسترسی، حالت اجباری را خاموش و دوباره ذخیره کنید.

اپ فقط لینک مستقیم APK از GitHub Releases همین مخزن را قبول می‌کند. دکمهٔ دانلود مرورگر Android را باز می‌کند. **نصب بی‌صدا ممکن نیست**: Android باید اجازهٔ نصب از منبع مرورگر و تأیید نهایی کاربر را بگیرد. برنامه پس از نصب/بازشدن دوباره نسخه را بررسی می‌کند. اگر دستگاه آفلاین باشد و قبلاً policy را دریافت نکرده باشد، تغییر تازه از سرور به آن نمی‌رسد.
