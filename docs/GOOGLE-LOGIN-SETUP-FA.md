# راه‌اندازی دکمهٔ ورود با Google — ساده و مرحله‌به‌مرحله

## اول بدانیم چه چیزی ساخته شده

آیکون رنگی G، ورود با **حساب Google** است، نه برنامهٔ Gmail. کاربر روی آن می‌زند، در صفحهٔ رسمی گوگل حسابش را انتخاب می‌کند و پس از تأیید به اپ و انتخاب زبان برمی‌گردد. برای اولین ورود با گوگل، فرم نام و کد ایمیلی لازم نیست؛ نام از حساب گوگل گرفته می‌شود. ورود قبلی با کد ایمیلی هم باقی مانده است.

این کد به حساب Google شما دسترسی مدیریتی ندارد. تنظیمات سرویس‌ها را باید خودتان در داشبوردهایشان انجام دهید. بدون تنظیمات زیر، دکمه هنوز امکان ورود واقعی ندارد. App Password قبلی Gmail فقط برای ارسال SMTP است؛ آن را در تنظیمات Google OAuth وارد نکنید.

## قدم ۱ — یک پروژهٔ Google بسازید

1. این نشانی را باز کنید: https://console.cloud.google.com/
2. با حساب خودتان وارد شوید.
3. بالای صفحه، روی انتخاب پروژه و سپس **New Project / پروژهٔ جدید** بزنید.
4. اسم پروژه را `Milo Login` بگذارید و **Create** را بزنید.
5. بعد از ساخته‌شدن، همین پروژه را انتخاب کنید.

اگر قبلاً پروژهٔ مناسب دارید، همان پروژه هم قابل استفاده است. فعلاً فقط همین قدم را انجام دهید و اگر صفحه با راهنما متفاوت بود، عکس بدون اطلاعات محرمانه بفرستید.

## قدم ۲ — صفحهٔ معرفی اپ به گوگل

در پروژهٔ انتخاب‌شده، **Google Auth Platform → Get started** را باز کنید. در بعضی نسخه‌ها نام بخش **APIs & Services → OAuth consent screen** است.

- **App name:** `Milo`
- **User support email:** ایمیل خودتان
- **Audience / User type:** `External`، برای حساب‌های Google خارج از سازمان خودتان
- **Contact email:** ایمیل خودتان
- مرحله‌های معرفی را تکمیل و ذخیره کنید.
- در بخش **Audience → Test users**، Gmail خودتان و کسانی را که فعلاً تست می‌کنند اضافه کنید. در حالت Testing فقط کاربران تست مجاز را برای آزمایش به‌کار ببرید.
- فقط دسترسی‌های معمول ورود، یعنی `openid`، `email` و `profile` کافی‌اند؛ دسترسی خواندن Gmail، مخاطبین، Drive یا پیام‌های خصوصی نمی‌خواهیم.

برای انتشار عمومی، وضعیت Audience/Publishing را طبق درخواست‌های همان داشبورد تکمیل کنید. اگر گوگل تأیید دامنه، سیاست حریم خصوصی یا بررسی برند خواست، آن را دور نزنید. اینجا قول فعال‌شدن عمومی بدون بررسی گوگل نمی‌دهیم.

## قدم ۳ — کلید اتصال Google را بسازید

1. در **Google Auth Platform → Clients → Create client** بروید (یا **Credentials → Create credentials → OAuth client ID**).
2. **Application type** را **Web application** انتخاب کنید. حتی برای APK هم همین نوع لازم است، چون این پیاده‌سازی از مرورگر سیستم و callback سرور Supabase استفاده می‌کند، نه SDK بومی Google.
3. نام دلخواه مثلاً `Milo Supabase Login` وارد کنید.
4. در **Authorized redirect URIs**، این نشانی را عیناً اضافه کنید:

```text
https://doagwkssxtxseuavrxnr.supabase.co/auth/v1/callback
```

5. روی **Create** بزنید. Google یک **Client ID** و یک **Client secret** می‌دهد.

**Client secret را در چت، عکس، فایل پروژه، Git یا متغیرهای EXPO_PUBLIC نگذارید.** فقط در داشبورد Supabase واردش کنید. نیازی به ارسال رمز Gmail، App Password یا کلید service_role نیست. در این روش ساخت Android OAuth client یا فرستادن SHA-1 به گوگل لازم نیست؛ اگر بعداً SDK بومی جداگانه انتخاب شود، تنظیماتش متفاوت است.

## قدم ۴ — گوگل را در Supabase روشن کنید

1. داشبورد همان پروژهٔ فعلی را باز کنید.
2. به **Authentication → Sign In / Providers → Google** بروید.
3. گزینهٔ فعال‌سازی Google را روشن کنید.
4. **Client ID** و **Client secret** قدم قبل را در کادرهای متناظر وارد کنید.
5. گزینه‌های امنیتی پیش‌فرض مثل بررسی nonce و email verification را ضعیف نکنید. گزینهٔ «اجازهٔ ورود با ایمیل تأییدنشده» را روشن نکنید.
6. تنظیمات را ذخیره کنید.

نشانی Callback که Supabase در همین صفحه نمایش می‌دهد باید با نشانی قدم ۳ یکسان باشد. اگر فرق داشت، پیش از ادامه مطمئن شوید پروژهٔ درست را باز کرده‌اید.

## قدم ۵ — نشانی برگشت به اپ را مجاز کنید

در **Supabase → Authentication → URL Configuration → Redirect URLs** این مورد را اضافه و ذخیره کنید:

```text
milologinv2://auth/callback
```

این نشانی برای APK زبان‌آموز **با لاگین** است؛ آن را در کادر Authorized redirect URIs گوگل نگذارید. گوگل اول به Supabase برمی‌گردد، و Supabase بعد به اپ شما.

اگر وب را هم استفاده می‌کنید، نشانی دقیق callback وب را نیز اضافه کنید. برای GitHub Pages فعلی:

```text
https://milanorezaee2.github.io/App2/auth/callback
```

برای یک آدرس وب دیگر، نشانی همان میزبان به‌اضافهٔ `/App2/auth/callback` است. اپ از origin فعلی استفاده می‌کند، نه localhost. اگر در آینده baseUrl حذف شد، callback هم `/auth/callback` می‌شود. فقط نشانی‌های مورد اعتماد و دقیق را اضافه کنید؛ wildcard عمومی برای همهٔ میزبان‌ها نگذارید. Site URL را هم نشانی واقعی وب خودتان قرار دهید، نه localhost.

برای تست وب در پیش‌نمایش Arena، آن را در تب مستقل مرورگر باز کنید و callback دقیق همان میزبان را مجاز کنید. صفحات ورود گوگل معمولاً داخل iframe نمایش داده نمی‌شوند.

## قدم ۶ — نصب نسخهٔ جدید و آزمایش

این دکمه در APKهای قدیمی وجود ندارد. پس از تکمیل تنظیمات باید APK جدید **زبان‌آموز با لاگین** از کد جدید ساخته و نصب شود. در Expo Go این ورود سفارشی پشتیبانی نمی‌شود.

1. با نصب تازه/نشست خارج‌شده روی آیکون G بزنید.
2. باید صفحهٔ رسمی انتخاب حساب Google در مرورگر سیستم باز شود؛ هرگز رمز گوگل را در خود اپ وارد نکنید.
3. حسابی را که در Test users گذاشتید انتخاب کنید.
4. پس از برگشت، باید صفحهٔ انتخاب زبان باز شود و انتخاب هر زبان کریدور خودش را باز کند.
5. یک بار ورود را لغو کنید؛ اپ نباید وارد حساب شود و ورود ایمیلی همچنان باید در دسترس بماند.
6. روی وب نیز برگشت و refresh را بررسی کنید. وقتی ایمیل OTP و Google هر دو با همان ایمیل تأییدشده استفاده می‌شوند، حساب/پیشرفت موجود را بررسی کنید؛ هیچ حسابی را برای آزمایش حذف نکنید.

## اگر خطا دیدید

- **redirect_uri_mismatch:** نشانی callback سرور در Google باید دقیقاً همان نشانی قدم ۳ باشد.
- **Access blocked / access_denied:** حساب تست را به Audience → Test users اضافه کنید و وضعیت انتشار/محدودیت‌های گوگل را بررسی کنید.
- برگشت به آدرس اشتباه یا localhost: Redirect URLs و Site URL در Supabase را بررسی کنید.
- «provider is not enabled»: تنظیمات Google در Supabase هنوز فعال یا ذخیره نشده است.
- کد callback نامعتبر/منقضی: دوباره از آیکون G شروع کنید. نشانی callback را برای دیگران نفرستید؛ فقط متن خطای بدون کد/توکن را ارسال کنید.
- اگر ورود سرور موفق شد ولی پروفایل ذخیره نشد، زیرساخت فعلی `app_user_profiles` و مجوزهای آن باید موجود باشند. برای این قابلیت migration جدید یا پاک‌کردن جدول لازم نیست.

## وضعیت فنی و تست

- OAuth authorization-code با PKCE و challenge نوع S256؛ تولید تصادفی امن و SHA-256 بومی Expo برای Hermes، و URL polyfill برای لینک‌های Android.
- تب مرورگر در وب، مرورگر امن سیستم در Android/iOS؛ بدون WebView و بدون درخواست مجوز Gmail.
- کد callback با سرور مبادله می‌شود؛ URL به‌تنهایی اجازهٔ ورود نمی‌دهد. کدها/خطاهای callback از تاریخچهٔ مرورگر پاک می‌شوند و داخل گزارش‌ها یا کش پروفایل نوشته نمی‌شوند.
- برگشت وب، cold-start موبایل، callback تکراری، لغو، شکست ساخت پروفایل و هم‌زیستی OTP با تست‌های شبیه‌سازی‌شده بررسی می‌شوند.
- دستورات: `npm run validate:google-login`، `npm run validate:email-login` و `npm run typecheck`.
- تست‌ها جای ورود واقعی با حساب Google روی APK جدید را نمی‌گیرند. تنظیمات دوردست Google و Supabase در این تغییر کد انجام نشده‌اند.
